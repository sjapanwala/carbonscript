CarbonScript

A lightweight, statically-typed scripting language inspired by C. One command per line, every value carries its type, and the interpreter points at the exact line that failed.

TypesAnnotated inline with a suffix: ;int, ;str, ;arr, …
Sigils?var reads a variable, $param a parameter, @fn calls a function
ErrorsEvery statement returns a numbered code, with a pointer to the failing line
Built inArrays, structs, file I/O, random numbers, sorting, CLI args
Latestv04.0/25: carbon functions, named fread, struct inspection
Install Try it in the browser Examples CarbonScript GPT ↗

Installation#

CarbonScript runs on Python. Clone the repository and run the installer, which puts the car command on your path.

RequirementsPython 3.10 or newer. The installer needs sudo access.
git clone git@github.com:sjapanwala/carbonscript.git
cd carbonscript/
chmod +x install.sh && sudo ./install.sh

To update later, run car --update. Check the installed version with car --v.

Vim / NeovimSyntax highlighting is available in syntax/vim_syntax.

Running code#

There are two ways to run CarbonScript.

Run a file

Save your code in a file ending in .car and pass it to car. Everything after the filename becomes a command-line argument.

car fizzbuzz.car 20

Interactive REPL

Run car with no arguments to open the live interpreter. Each line runs as soon as you press enter. Type carbon quit to leave.

$ car
?? >> set name = "Ada";str
?? >> stdout "Hello" ?name
Hello Ada

Your first program#

Here is a function that adds two numbers, next to the same thing in JavaScript.

JavaScript
function add(a, b) {
  return a + b;
}
console.log(add(2, 3));
CarbonScript
func;int add $a;int $b;int {
  return ( $a + $b )
}
set total = @add 2 3
stdout ?total

The function declares its return type (func;int) and a type for each parameter ($a;int). Math goes inside parentheses, and you call a function by prefixing its name with @.

Syntax basics#

CarbonScript runs one line at a time. The interpreter splits each line on spaces into tokens and resolves them: it substitutes variables, evaluates math and runs function calls. It then passes the result to the command named by the first token. Text inside double quotes stays together as a single token.

Most of the syntax comes from a few prefixes and suffixes:

SyntaxMeaningExample
?nameRead a variable's valuestdout ?name
$nameRead a function parameter (inside a function body)return ( $a + $b )
@nameCall a functionset x = @square 4
value;typeAnnotate a value's typeset age = 25;int
( … )Math or logic expression( ?a * 2 )
name:fieldTarget a struct field for assignmentset user:age = 30
?name.fieldRead a struct fieldstdout ?user.age
?arr[i]Index into an array or string?args[?iteration]
//Comment (whole line, or the rest of the line)// hello

Output#

CarbonScript uses standard I/O. stdout prints all of its tokens to the console, joined by spaces. You can mix strings, variables, math and function calls freely.

stdout "Hello World"
stdout "Sum:" ( 2 + 3 )
stdout "Hi" ?uname

Use clear to clear the terminal.

Data types#

Add a type to a value with a semicolon suffix. If you leave it off, set and const work out the type from the value.

TypeDescriptionExample
intWhole numbers, positive or negativeset x = 10;int
fltNumbers with a decimal pointset x = 10.5;flt
strA sequence of charactersset x = "Hello";str
booltrue / false, stored as 1 / 0set ok = true;bool
arrAn ordered list of valuesset x = 1,2,3;arr
structA named group of fieldslet user;struct
voidNo value; the default for an empty declarationlet x;void
cstrA string stored as its carbon numberset c = "hi";cstr
Array literalsWrite array literals as comma-separated values with no spaces, e.g. 1,2,3;arr. To store values of different types, declare an empty array and push typed values into it.

Use type(x) to get the name of a value's type as a string.

set pi = 3.14;flt
stdout type(?pi)   // flt

Variables#

There are three keywords for declaring variables:

KeywordMutableUse it for
setyesNormal variables. Running set again overwrites the value.
constnoValues that must never change. Reassigning one is an error.
letyesDeclaring a name with a type but no value yet, such as an empty array or struct.
const name = "John Doe";str
set age = 25;int
set graduated = false;bool
let scores;arr

stdout ?name "is" ?age

Increment & decrement

increm and decrem add or subtract 1 from a mutable int variable in place.

set i = 0;int
increm ?i
stdout ?i   // 1

Input#

stdin shows a prompt, reads a line from the user, checks it against the type you declared, and stores it in a new variable.

stdin name;str "What's your name?"
stdin age;int "How old are you?"
stdout "Hi" ?name

Supported input types are str, int, flt and bool.

Math & logic#

Every math or logic expression goes inside parentheses, with spaces between tokens. Nested parentheses are supported.

set x = 10;int
stdout ( 100 + ?x )
stdout ( ( ?x * 2 ) - 5 )
set even = ( ?x % 2 == 0 )
KindOperators
Arithmetic+ - * / % **
Comparison== != > < >= <=
No operator precedenceExpressions are evaluated left to right. Use nested parentheses to control the order. There are no logical operators (&&, ||), so combine conditions by chaining if / ifelse.

Rounding

ceil() rounds up and floor() rounds down.

set x = 3.14;flt
stdout ceil(?x)    // 4
stdout floor(?x)   // 3

The constants ?pi (3.14) and ?eu (2.72) are built in, as are ?true and ?false.

Conditionals#

Each conditional fits on one line: a condition in parentheses, followed by one statement to run.

  • if starts a chain.
  • ifelse is checked only if nothing earlier in the chain matched.
  • else runs if nothing in the chain matched.
set x = 10;int
set y = 5;int
if ( ?x > ?y ) stdout "x is larger than y"
ifelse ( ?x < ?y ) stdout "x is smaller than y"
else stdout "x and y are equal"
Aliasesfi, elsefi and default are the interpreter's internal names for if, ifelse and else. Either spelling works.

Loops#

Loop bodies go inside braces. Inside a loop, ?iteration holds the current pass number, starting at 0.

repeat: fixed count

Runs the body a fixed number of times. The count can be a number or a variable.

repeat 5 {
  stdout "pass" ?iteration
}

do: counting condition

Starts at a value and adds 1 after each pass. The loop keeps going while the comparison is true. Supported comparisons: < > == <= >=.

do 0 < 5 {
  // runs 5 times
  stdout ?iteration
}

until: run until a value

Runs the body until a variable equals a target value.

set n = 0;int
until n = 3 {
  increm ?n
}
File modeLoops and functions read their bodies from the source file, so use them in .car files rather than the REPL.

Arrays#

Arrays work like stacks: push adds to the end and pop removes from the end.

Creating & pushing

set nums = 1,2,3;arr          // literal: no spaces

let mixed;arr                   // empty array
push mixed 1;int "hello";str 3.14;flt

Popping

pop removes the last item and stores it in ?pop.

pop nums
stdout ?pop    // 3

Indexing

Indexes start at 0 and can be computed.

stdout ?nums[1]            // 2
stdout ?args[?iteration]

Length

length stores the size of an array or string in ?len.

length ?nums
stdout ?len

Sorting

sort puts a sorted copy in ?sorted and leaves the original array unchanged.

let x;arr
push x 89 1 45 -120 12
sort ?x
stdout ?sorted   // [-120, 1, 12, 45, 89]

Structs#

A struct groups named fields under one name. Declare it with let, then assign fields with name:field.

let profile;struct
const profile:name = "John Doe";str
set profile:age = 45;int
set profile:graduated = true;bool

stdout ?profile.name
stdout ?profile.age

struct profile     // pretty-print every field

Fields assigned with const can't be changed later. Run carbon structs to list every struct you've defined.

Functions#

As in C, you declare the return type up front, or void if the function returns nothing. Parameters start with $ and each one needs a type.

func;<return_type> <name> $param;type … {
  // body
  return <value>
}

Defining

func;int addition $x;int $y;int {
  return ( $x + $y )
}

func;void greet {
  stdout "Hello!"
}

Calling

Call a function with @ followed by its arguments. If it returns a value, store the result in a variable.

set result = @addition 10 20
stdout ?result     // 30
@greet

Carbon numbers#

A carbon number encodes a string as one large integer. Each character becomes its 3-digit ASCII code, and a 4-digit length is added at the end. Because the result is a plain number, you can compare it with any other value, whatever its type.

  • cnum(x) converts a string to a carbon number.
  • ascii(x) converts a carbon number back to a string.
set x = "CarbonScript";str
set c = cnum(?x)    // 670971140981111100830991141051121160012
set s = ascii(?c)   // CarbonScript

Command-line arguments#

Arguments passed after the filename are stored in the ?args array. Unfilled slots contain the carbon number for "void", so you can check whether an argument was given by comparing with cnum("void").

if ( ?args[1] != cnum("void") ) set runIterations = ?args[1]
else set runIterations = 10;int
@generateFibonacci ?runIterations

This uses the argument if one was given and falls back to 10 otherwise.

File I/O#

First pick a file with fset. Later file commands all act on that file.

CommandDescription
fset <path>Choose the file to work with
fwrite <tokens…>Append a line to the file
fread <name>Read the file into a struct called name
fclearErase the file's contents
fset notes.txt
fwrite "Buy milk"
fwrite "Ship v5"

fread notes
stdout ?notes.contents   // array of lines
stdout ?notes.len        // number of lines
stdout ?notes.type       // file extension

fclear

Random numbers#

rand min max stores a random integer between min and max, inclusive, in ?rand.

rand 1 100
stdout "You rolled" ?rand

File rules#

Put RULE lines at the top of a .car file to change how the interpreter runs it.

RuleEffect
RULE hide-errorsSuppress formatted error output
RULE show-ecPrint the error code after every statement
RULE show-tkPrint the token array for every statement (debugging)
RULE force-runKeep running after an error instead of stopping
RULE force-dontrunRefuse to run the file at all
RULE hide-errors
RULE show-ec

stdout "rules applied"

Carbon system calls#

Commands that start with carbon (or * for short) inspect the interpreter's state. They're most useful in the REPL.

CommandDescription
carbon varsList all variables with their types and whether they can change
carbon funcsList all functions with return types and parameter counts
carbon structsList all structs
carbon historyTable of every error code produced in this run
carbon quit [code]Exit the interpreter
run <file.car>Run another .car file from inside a script

Reading diagnostics#

When a statement fails, CarbonScript stops and prints a diagnostic. This one comes from a function header where $a has no type:

function:type error: no function intake type specified for $a
main.car:1:3
 |
1| func;int addNums $a $b;int {
 | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^ unexpected type interaction.
error: aborting due to status code 3
  1. What went wrong. The part of the interpreter that raised the error (function), the kind of error (type error), and a hint.
  2. Where. file:line:code. Here that's main.car, line 1, error code 3.
  3. The code. The failing line, with carets under the problem. In a terminal, each error code has its own color.
  4. The result. The run was aborted with the status code shown. To keep going after errors, use RULE force-run.

Error codes#

Every statement returns a code, which is stored in ?errorlevel. Any code other than 0 or 2 stops the file, unless the file uses RULE force-run.

Changelog#

v04.0/25 latest April 5, 2025

  • Carbon functions. Prefix a keyword with carbon or * to call an interpreter function: * funcs, * vars, * history, * quit.
  • Named fread. Choose the struct that file contents are read into: fread hello, then ?hello.contents.
  • Struct inspection. * structs lists all structs, and struct name pretty-prints one.
  • Elevated variables. errorlevel, iteration, rand, pop, len and sorted are now updated by the runtime only.
  • New error codes 16 and 17 (initialization), a refreshed listing UI, and a to-do list demo that uses file I/O.
  • Bug fixes and code cleanup.
